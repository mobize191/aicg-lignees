Demande de Marc-Olivier du 14/11 : le front UX (PR #12) est livré mais le rendu reste mauvais ; tranchage B acté : maquette d'abord, chantier ensuite. Référence : docs/design/recherche-ecran-combat-2026-11-14.md. Les maquettes APRÈS sont interactives : clique une unité (fiche flottante), puis un sort d'attaque, puis une cible (illumination + confirmation au-dessus du point de contact + mini-log). Ajouts v2.1 : chiffres PV/PVmax, MP et bouclier sur les unités ; icônes agrandies (74 px, boss 118 px). Ajouts v2.2 : module boss sans chevauchement (sbires écartés du boss) ; invocations = petits carrés (40 px) en PREMIÈRE LIGNE, rangée dédiée devant chaque camp (rien à décaler, rien par-dessus), cliquables (fiche, PV mini, badge ⏳ ttl) ; chip pointillé 👁 dans le rail d'ordre.

Notes d'implémentation (pour le prompt couloir 1)

  • Invariant conservé : la fenêtre ne recouvre jamais le terrain ; la barre compacte réduit encore l'emprise (38 % → ~28 % en portrait).
  • Chiffres sur les unités : PV/PVmax et MP/MPmax en clair à côté des barres (lisible sans fiche) ; bouclier = fine barre dorée AU-DESSUS de la barre PV + badge chiffré (le bouclier s'affiche avant les PV dans l'ordre de lecture).
  • Tailles d'icônes : unités 74 px, boss 118 px + nom en gras + chip élargi (👑 36 px) dans le rail d'ordre ; dans le module boss, sbires écartés du boss : aucun chevauchement.
  • Invocations = petits carrés en première ligne (tranchage 7-b) : carré 40 px à bordure pointillée, placé dans une RANGÉE DÉDIÉE devant le camp (l'« avant » de la formation, vers le centre du terrain) : rien à décaler, rien par-dessus les unités ; cliquable → fiche de l'invocation (stats dérivées, ttl) ; PV mini + badge ⏳ tours restants sur le carré ; un actif max par lanceur ; le bouton d'invocation vit dans la barre de commandes, et le chip pointillé 👁 rejoint le rail d'ordre du tour.
  • Pure UI : HTML/CSS uniquement, aucun changement moteur ni data : digest inchangé attendu (les invocations elles-mêmes relèvent du chantier sorts en cours).
  • Cibles tactiles ≥ 44 px (WCAG 2.5.5) ; sort indisponible = grisé, jamais masqué (contrainte visible, leçon TCG Pocket).
  • Feedback d'occlusion : la confirmation de ciblage et les dégâts flottent au-dessus de l'unité, jamais sous le pouce ; le mini-log (3 lignes) reste juste au-dessus de la barre.
  • À trancher ensuite : vitesses par contexte (§0 n°5, après test terrain de cette maquette).
